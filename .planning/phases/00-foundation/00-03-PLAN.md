<objective>
Define per-service Pydantic Settings subclasses per D-16..D-23 with anti-leak boundary (DataPlatformSettings has no `mexc_trade` field), SecretStr-typed credentials, `safe_summary()` method on every class, and the `assert_no_trade_env_leaked()` startup guardrail on data-platform.

Purpose: This is the env-var-routing boundary. Per D-16, each service can only structurally see env vars matching its Settings class fields. A misrouted `MEXC_TRADE__SECRET` env var visible to the data-platform service is FOUR ways inert: (1) `DataPlatformSettings` has no `mexc_trade` field, so pydantic-settings ignores it; (2) `assert_no_trade_env_leaked()` runs at startup and crashes the service if it sees the var; (3) `SecretStr` prevents accidental logging; (4) `safe_summary()` is the only log-line shape allowed for settings (never `repr(settings)`, per D-21 and UI-SPEC.md §Severity).

Output: 5 source files (base, data_platform, strategy_engine, dashboard, risk_guard) + 4 unit test files covering fail-fast, safe_summary-no-secrets, anti-leak, env-nested-delimiter routing. Plan 00-05 (FastAPI entrypoints) and Plan 00-07 (Railway config) consume these classes.
</objective>

- `BaseAppSettings(BaseSettings)` shared base with `SettingsConfigDict(env_file=_env_file(), env_nested_delimiter='__', case_sensitive=False, extra='ignore')`
- Per-service subclasses inherit; each owns its specific fields
